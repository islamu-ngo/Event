## Summary
Planned first public beta scope for the ISLAMU Event Platform with a production-oriented API baseline.
This release delivers core event and organization workflows, multi-tenancy, HATEOAS APIs, strong auth/authz, caching, observability, and full test-pyramid foundations.

**Pre-1.0 notice:** `0.y.z` indicates initial development and API instability is still expected before 1.0.0.

## Implemented (v0.1.0)

### Breaking Changes
- None identified in this frozen planning baseline.

### Features
- **api:** Event, organization, tenant, identity, and admin endpoint surface with consistent route contracts.
- **api:** HAL/HATEOAS support with relation links, policy-aware link filtering, and `Prefer: return=minimal` behavior.
- **api:** Security model with JWT/OIDC validation, claims fallback (`sub` -> `nameidentifier` -> `sid`), policy matrix, and pipeline authorization checks.
- **api:** Runtime protections including rate limits, request timeout policies, response compression, ETag conditional responses, and graceful shutdown behavior.
- **api:** OpenAPI ecosystem with native docs endpoint, Swagger OAuth UI, Scalar reference UI, and DTO/client contract workflow.
- **api:** CQRS application layer with handler boundaries, manual validator flow, command response envelopes, and pagination contracts.
- **db:** Domain and persistence baseline with tenant/audit/soft-delete contracts, specification query pipeline, outbox foundations, and startup seeding.
- **db:** Global named query filters, audit interception, soft-delete interception, and controlled hard-delete path.
- **devops:** Platform defaults for structured logging, service defaults, observability exporters, readiness/liveness checks, and Prometheus endpoint.

### Performance Improvements
- **db:** No-tracking reads, compiled hot queries, split include strategy, and index/include tuning foundations.
- **api:** Hot endpoint benchmarking baseline and performance behavior for long-running request detection.

### Refactors
- **api:** Response envelope consistency pass across API endpoints.
- **api:** Handler orchestration cleanup to reduce duplicated request flow logic.

### Documentation
- **devops:** Architecture, operations, troubleshooting, multi-tenant behavior, deployment modes, and contributor workflow guides.
- **api:** Relation naming, DTO regeneration process, trust-boundary guidance, and module filter behavior notes.
- **db:** Query-filter bypass and operational data-access guidance.

### Testing
- **api:** Integration suites for controllers, middleware, problem-details, caching, rate limits, and authorization behavior.
- **db:** Repository container tests and entity invariant checks.
- **ui:** Blazor filter test coverage via bUnit.
- **devops:** Layer-rule, CQRS convention, and API convention verification suites.

### Chores / DevOps
- **devops:** CI baseline workflow, release build gate, per-project test gate, and TRX failure evidence workflow.
- **devops:** Namespace/style guidance and AI-assist consistency docs for project contributors.
- **ui:** Typed client regeneration workflow from OpenAPI outputs.

## Known Limitations
- Federation protocol endpoints and full interop remain planned for v1.0.0 scope.
- Enterprise-next capabilities (bulk import, Redis-backed evolution, RabbitMQ + MQContract, webhooks platform, MCP server) are planned for v1.0.0.
