# October 2026 .NET Dependency Security Patches

## Decision and scope

On 2026-10-19 the Project Steward authorized replacing the vulnerable dependencies
blocking the moderation migration tool and continuing implementation. The selected
changes raise existing package-family security floors; they do not change the target
framework, installed SDK, shared runtime, application configuration or audit policy.

| Package | Selected version | Owning dependency path |
| --- | --- | --- |
| System.Security.Cryptography.Pkcs | 10.0.13 | Explicit floor in Explore.Secrets, where Microsoft.Data.SqlClient introduces Pkcs |
| System.Security.Cryptography.Xml | 10.0.13 | Explicit floor in Explore.Persistence, where EF Data Protection introduces Xml |
| Microsoft.AspNetCore.Components.Web | 10.0.13 | Required by the patched WebAssembly package |
| Microsoft.AspNetCore.Components.WebAssembly | 10.0.13 | Required by the patched WebAssembly Server package |
| Microsoft.AspNetCore.Components.WebAssembly.Server | 10.0.13 | Existing Explore.Blazor server dependency |
| Microsoft.AspNetCore.DataProtection.StackExchangeRedis | 10.0.13 | Existing Explore.Blazor Redis Data Protection path, independent of Persistence |
| Microsoft.AspNetCore.SignalR.Client | 8.0.32 | Explicit floor in Event.Standalone for Quartz.Dashboard's existing SignalR 8 family |
| MessagePack | 3.1.9 | Existing Explore.AppHost KubernetesClient graph |

Versions are centrally declared in `Directory.Packages.props`. Direct floors are
placed at the actual introducing product owners, not in test projects or the Domain.
Global transitive pinning was not enabled. WebAssembly.Authentication remains at its
existing compatible version. Required transitive dependencies and project-reference
closures are generated by NuGet, not manually edited into lockfiles.

An attempted direct Xml reference in the Blazor Web SDK project raised NU1510
because that reference is supplied/pruned by the shared framework. It was removed;
updating the actual Redis Data Protection parent repairs its non-Web consumers
without suppressing NU1510 or adding a redundant runtime dependency.

## Security and verification evidence

The original restore stopped on Pkcs advisories
[GHSA-2fmv-rv2c-59x7](https://github.com/advisories/GHSA-2fmv-rv2c-59x7) and
[GHSA-846f-f764-76mx](https://github.com/advisories/GHSA-846f-f764-76mx).
Downstream restores exposed additional existing graphs, including WebAssembly Server
[GHSA-g27p-qf6j-c96c](https://github.com/advisories/GHSA-g27p-qf6j-c96c) and
[GHSA-qjpx-jqm5-h2c4](https://github.com/advisories/GHSA-qjpx-jqm5-h2c4), MessagePack
[GHSA-qhrr-8q5h-9q3h](https://github.com/advisories/GHSA-qhrr-8q5h-9q3h), and SignalR
[GHSA-334f-vvp4-7g6p](https://github.com/advisories/GHSA-334f-vvp4-7g6p).
The separate Blazor Redis path also exposed vulnerable Xml/Pkcs resolutions; it was
repaired through its product parent rather than by changing test-only dependencies.

The affected product and test dependency graphs were restored with security auditing
and warnings-as-errors unchanged. Restoring test dependencies did not build, discover
or execute tests. Structured inspection found all 38 persisted Pkcs/Xml entries in
the 22 original affected project lockfiles resolving to 10.0.13. Remaining lower
numbers in parent dependency minimums are not the resolved package versions.

The final API-test graph refresh and two locked-mode checks physically exited 0
without vulnerability warnings:

```bash
dotnet restore tests/Event.API.IntegrationTests/Event.API.IntegrationTests.csproj --force-evaluate --verbosity minimal
dotnet restore src/Explore.AppHost/Explore.AppHost.csproj --locked-mode --verbosity minimal
dotnet restore tests/Event.API.IntegrationTests/Event.API.IntegrationTests.csproj --locked-mode --verbosity minimal
```

Eight affected product builds physically passed with zero errors: Secrets (12 warnings),
Persistence (62), Infrastructure (45), API (2), Blazor Client (230), Blazor server (13),
Standalone (0) and AppHost (6). Existing warnings were not suppressed or claimed fixed.
The repository's native dependency-license metadata check also passed for 531 unique
package/version pairs; its four pre-existing visible exceptions remain in force.
That check is not legal advice or assembled-artifact license certification.

Structured assertions against the tracked lockfiles printed
`TRACKED_SECURITY_FLOOR_RESOLUTIONS_OK`. The same native SQLite migration-tool command
that previously failed during restore now exits 0 and generated
`20261019145153_AddNativeModerationSourceOwners` plus its designer and model snapshot.
PostgreSQL (`20261019145245`), SQL Server (`20261019145818`) and MySQL
(`20261019145843`) generated the same named source migration with their own designers
and snapshots; MariaDB shares MySQL. All four owning projects then compiled with zero
errors. A separate SQL Server model-policy cascade correction generated additively as
`20261019151338_PreservePrivateBirthDatePiiCascade` and compiled (0 warnings/errors),
not by editing dependency metadata or generated history. Its downgrade contains an
unresolved case-evidence FK predecessor discrepancy; compilation is not reversal proof.
This demonstrates that the original restore blocker was removed,
not that any migration has been applied or tested.
No audit suppression, runtime exploitability assessment, installed SDK/runtime
security certification, database application, test execution or programme readiness
is claimed. No evidence of compromise was established by package version findings.
