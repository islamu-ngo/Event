Move the AddOns and ticketing-recovery cases into the ordinary domain lane; preserve real refund races, privacy replay and email ambiguous-outcome tests.

New trust boundaries or secret exposure still require normal escalation.

### IVSD-F012 — Distinguish test profiles from enabled runtime and external authority proof

An authenticated test host can exercise real login while disabling outbox, email processing or rate limits. A fixture can supply a valid in-memory external key ring without establishing production operator provisioning. A source catalogue can describe required worker behavior without executing it. Combining these valid but limited facts into a general readiness claim would mislead operators and affected users.

Retain their actual contributions, then name the additional profiles that remain necessary: enabled non-Testing startup/worker/recovery, selected external identity/erasure/key authority, cross-host session continuity and revocation. Record tested commit, provider, credential purpose, authentication and topology accurately. Preserve `not-attested` where the existing packet has no observed fact. This implements truthful reporting (Sidq) and entrusted-data stewardship (Amanah) without adding a duplicate admission system.
