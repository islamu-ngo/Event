# Owned browser assurance

> Audience: contributors maintaining real runtime/browser verification.
> Owner: `Event.Distributed.IntegrationTests`, `Browser` profile.

`BrowserJourneyTests` drives Chromium through Microsoft.Playwright .NET under TUnit. Each journey creates an `OwnedAppHostFixture` in the non-Testing Assurance environment, starts the real Split topology, and waits for its migration and health contract. The fixture owns ports, stores, volumes, bootstrap identity and environment-generated credentials. A new nonpersistent browser context owns cookies and cache for each journey. Disposal closes the context before the browser and driver, then disposes the AppHost owner. Discovery does not install Chromium or start services.

The local configured administrator starts with a temporary password. Each journey first submits that password through the real login form, verifies the password-replacement page is still anonymous, changes the password through that form, and verifies replacement itself did not authenticate the browser. Subsequent sign-in uses the new fixture-owned password. No authentication service, database seed, WebApplicationFactory or local-agent persona substitutes for this lifecycle.

| Journey | Observable invariant |
| --- | --- |
| Login/logout | Successful credentials grant the protected create-event page. The journey captures every HttpOnly `.AspNetCore.Cookies*` cookie in memory, including chunks, then performs real logout. Both the original context and a fresh context replaying the unchanged cookies must be anonymous and challenge on the protected page. An already-connected Interactive Server resources page on the peer BFF must deny its next protected export action. A fresh independent session must still access that export. |
| Browser cookie expiry | Expiring the real HttpOnly session cookies in the browser removes access; fresh credentials restore it. This does not prove server-side JWT expiry. |
| Server token expiry | A real five-minute token first accesses the protected ticket-management endpoint. Bounded condition-driven polling observes its rejection, then confirms the browser session is anonymous and challenges again. |
| Keyboard and languages | Tab reaches the password field, Enter submits, the language menu works by keyboard, Arabic sets RTL, refresh retains the choice, English restores LTR and the skip link focuses the main landmark. |
| Tenant boundary | Two real tenants are created through HTTP. A public ticket catalog is visible under its owning route; the other route cannot expose it even with a forged browser tenant header. |
| Free registration | Public API setup creates an event and published free catalog. Browser reservation and finalization produce a confirmed order that survives reload; both the public HAL result and UI remove the finalize action. |
| Workspace accessibility | The real Studio sidebar opens by keyboard as a mobile modal; Tab and Shift+Tab remain inside, Escape closes it and restores its opener. The desktop dock stays nonmodal and allows focus to leave. English/Arabic panel geometry mirrors without desktop content overlap, mobile navigation stays inside the viewport, and a whitespace resource title produces a visible associated error before Cancel restores focus. |
| Workspace authority | An administrator provisions a separate ordinary Local identity through the public operator API. Its fresh browser performs mandatory password replacement and sign-in; its signed HTTP requests receive no manage-resources HAL relation and a 403 management result. The rendered Studio resources route exposes no creation form or action. |

Setup HTTP calls perform the ordinary create/draft/publish commands and use the current event concurrency stamp. Registration itself occurs through the rendered UI. Assertions use labels, roles, visible status and public JSON contracts. There are no arbitrary readiness sleeps or intercepted/fabricated responses. The selected free ticket collects no participant details and requires no external payment provider. These checks complement existing domain, persistence, BFF, authorization and accessibility suites; they are not a WCAG certification or the complete payment/tenant threat model.

Captured-cookie replay adds a server-side logout guard within the existing journey; it does not add a separate identity or change the profile count. Cookie values and metadata remain in memory, with the original expiration, domain and path preserved. This journey selects the two-BFF shared-authority profile and creates an active tenant and published event through public APIs. The peer's management HAL export link and successful protected request establish its initial authority. A live socket on the exact BFF circuit path and opening and cancelling the real resource form corroborate the explicitly Interactive Server route; socket URLs, query values and frames are never exported. After logout on the original host, the test performs no peer navigation or reload: clicking its export button must expose the anonymous sign-in control and produce no export result or download. The peer can retain its resources URL or follow the existing route guard to sign-in. The inbound circuit guard revokes before dispatch, so the assertion does not require an unreachable resource-service error message. A fresh independent login must still receive a successful protected export response. The guard checks the next protected operation; it does not require an existing SignalR principal to change automatically. These real-host results remain unverified until runtime startup is healthy; compilation or clearing the original browser's cookies does not prove them.

Event setup selects MultiTenant mode and creates an active tenant with current-user administrator membership through the ordinary Tenant API. The configured bootstrap's provisioning tenant is not silently treated as active or changed through a private store. Studio's real navigation panel is `shell.workspace-nav` in the Shell dock scope; a synthetic Workspace-scope descriptor does not prove its behavior. Native input validation allows a whitespace-only value through `required`, after which Event's own title validation supplies the associated visible error. Responsive assertions wait for rendered projection changes rather than sleeping for the viewport observer.

## Artifact boundary

`BrowserArtifactPolicy` admits only fixed journey/outcome codes. Browser traces, HAR, storage state, videos, screenshots, console output, arbitrary filenames, response bodies and raw exceptions are not admitted. The owner configures no recording or storage export, and the journey boundary replaces exceptions with a code that has no inner exception, data payload or raw message. The Harness tests include a generated sensitive canary and prove it cannot survive exception sanitization. No screenshot is currently admitted, so there is no unmasked screenshot path.

Nonempty `DEBUG` or `PWDEBUG` is rejected before host/browser startup because driver logging can bypass exception sanitization. Do not add raw failure attachments in CI. A future visual artifact requires a separate reviewed allowlist, masking of every sensitive surface, canary tests and an explicit retention policy before use. Runtime-side logging has its own secret/redaction contract; absence of browser artifacts does not certify every service log.

## Execution and evidence

See the [public browser testing guide](../../public/documentation/readme/contributing/browser-testing.md) for install and run commands. Run `BrowserArtifactPolicyTests` in the Harness profile without browser/container startup. Execute the Browser profile only with the admitted package, installed Chromium and owned runtime prerequisites. Record named pass/fail/skip counts and candidate commit; a build, discovery or Harness pass does not close the real browser profile.

`eng/tools/InstallAssuranceBrowser.cs` is the explicit native .NET installation entrypoint. It pins the admitted Microsoft.Playwright 1.64.1 package, rejects all arguments and invokes only the public `Microsoft.Playwright.Program.Main` Chromium-install action with `--only-shell`. The returned status is preserved. This avoids downloading unused full Chrome and Widevine. Set `PLAYWRIGHT_BROWSERS_PATH` to a task-owned headless-only cache and use that same path for the tests. The tool has no test/discovery hook, Node helper, PowerShell dependency, system-package installation or arbitrary CLI forwarding.

The initial implementation must be validated against a healthy configured-administrator fixture. Server JWT expiry is separate from browser-cookie expiry and takes at least five minutes of real server time. The fixture selects the existing five-minute minimum through `Authentication:Local:AccessTokenLifetimeMinutes`; a six-minute deadline bounds condition-driven endpoint polling. No product validator or clock is substituted.

`BrowserSecurityVectorTests` executes the repository's real recovery, registration-proof and guest-status scripts in fresh Chromium documents. Native Playwright routes serve only those product modules and inject HTTP or clipboard failures at the browser boundary. These isolated vectors prove browser-module behavior, not server authentication or hosting. The user-approved scripting exception is limited to Playwright browser API/module expressions and the worker progress callback bridge; it does not admit Bun, Node, npm, helper scripts or a copied JavaScript harness.

Recovery vectors check all seven pointer fields, once-only decoding and consumption, fragment/query erasure before antiforgery and mutation, invalid pointers, endpoint refusal and one 409 response without retry or response-body parsing. The real dedicated worker must solve difficulty 16 and 17; an independent native C# SHA-256 oracle checks most-significant bits, a known negative, and an altered envelope. Other cases check progress from zero, busy refusal, cancellation, reuse and nine malformed/expired challenge variants. Guest vectors cover exact route and order binding, nested document base paths, one-shot consumption, malformed and query input, explicit clipboard failure, and a real private-link download whose blob URL is revoked. Downloads are read in memory and explicitly deleted before context disposal.

`ActualHostFirstNonceScriptScrubsPrivateInputBeforeSubsequentNetwork` is unconditional and starts its own genuine configured-administrator Split host. It renders both root and actual tenant-path documents, verifies the first head element is the nonce-bearing script authorized by the response CSP, observes clean location state at subsequent request interception, and compares copied links with the rendered base URI. Valid and malformed private input must be erased. Route-isolated document tests do not stand in for this host check. The original three JavaScript security-test files remain until the native vectors and actual-host case have passing execution evidence.
