# Configurator extraction: durable ownership boundaries

The approved extraction keeps configuration authority in Event and transfers
only offline preparation to ISLAMU Configurator. Destination readiness precedes
source removal. The parent confirmed destination runtime, package, architecture
and engineering readiness before Event's literal source cleanup. Preliminary
Event checks were not used as a substitute for that destination evidence.

Event's definition exporter owns environment metadata, parser reference vectors,
canonical family/revision/digest receipts and host-wire acceptance. It references
Domain and Wire only. `--check-local` makes its read-only CI gate independent of
a sibling checkout; `--check-environment` preserves catalogue freshness.

SetupLive client transport moved to `Explore.Blazor.Client/Services/SetupLive/`
and its tests to `Explore.Blazor.Client.Tests/SetupLive/`. Backend enrollment,
secret-binding, persistence and authorization stayed in Event. The 35-case serial
API security lane must not disappear with the seven setup test projects: it has
a separate retained CI step with TRX and optional coverage.

Shared DI and YamlDotNet have retained callers and are not setup-only packages.
Avalonia, CommunityToolkit.Mvvm, ISLAMU.Terminal.Gui and Spectre package removal is scoped
to their last setup callers; the terminal feed/probe disposition follows that
same caller proof. Historical legal/provenance records are not disposable build
inputs.

Live Configurator integration is an explicitly excluded future workstream,
not a substitute for a missing extraction outcome. See
[the ADR](../../../docs/internal/adr/ADR-configurator-extraction.md) and
[the live integration backlog](../../backlog/configurator-live-integration.md).
